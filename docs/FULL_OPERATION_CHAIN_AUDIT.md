# 全功能实际操作链路审计

> 发布状态：**冻结生产部署**。
>
> 审计基线：`944a54f7f6efa1b0725ad43f35a7a6bea8145152`

本轮不把接口存在、静态编译、Mock 测试或绿色 CI 直接解释为功能正常。每条业务链路必须核对：

1. 页面入口与权限；
2. 请求参数与 BIGINT 精度；
3. DTO 运行时校验；
4. 服务端状态机；
5. 数据库、库存、积分、优惠券和文件副作用；
6. 支付/退款等外部系统结果；
7. 返回结构与前端回显；
8. 页面刷新后的持久化回查；
9. 取消、超时、并发、重试和补偿路径。

## 已确认的发布阻断项

### 促销定价

普通订单创建服务虽然声明内部 `priceOverride`，实际金额和订单项仍始终使用 SKU 原价。秒杀传入秒杀价不会生效；拼团下单也没有传入拼团价。

### 秒杀状态机

- 秒杀锁过期后发生成功支付时只记录 warning，没有可靠退款或自动补偿闭环。
- 普通订单创建成功后，秒杀订单记录创建失败会造成普通订单与秒杀库存锁不一致。
- 普通订单超时关闭后没有可靠执行秒杀取消钩子。

### 拼团状态机

- 失败/过期团只标记失败，已支付成员没有自动退款。
- 开团/参团先创建普通订单，后创建成员记录；后一步失败会遗留无法关联的普通订单。
- 接口允许购买数量，但拼团成员没有数量字段，支付后活动售出数量按成员数而不是购买数量累计。
- 可加入团列表使用 `Number(BigInt)` 作为 Map 键，大 ID 会丢精度。
- 拼团多项 DTO 仍把数据库 BIGINT ID 转换为 JavaScript number。

### 验收证据不足

管理后台当前没有浏览器级 E2E。`test:admin` 只执行待清理素材队列的 Node 测试，不能证明登录、菜单权限、表单填写、上传、保存、刷新回查、订单发货、退款和核销等真实操作链路。

## 处理原则

- 新测试必须能在旧实现上失败，在修复后通过。
- 促销价格只能由服务端活动记录计算，不能信任客户端价格。
- 普通订单、促销记录、库存与支付后置处理必须处于同一事务，或形成持久化、可重试、可审计的补偿任务。
- 无法安全闭环的资金功能不得以 TODO、warning 或人工记忆作为上线方案；生产入口必须显式关闭。
- 修复完成后重新执行全新 MySQL 迁移、真实数据库状态机、HTTP 链路、管理后台浏览器操作、小程序测试、三端构建、生产 Docker 镜像、CI 与 Release Gate。

本文件会随审计进展更新；在所有 P0 阻断项关闭前，不生成生产部署命令。
